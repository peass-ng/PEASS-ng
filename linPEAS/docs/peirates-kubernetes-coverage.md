# Peirates coverage in linPEAS

This audit uses [Peirates' command manifest](https://github.com/inguardians/peirates/blob/main/docs/commands/manifest.tsv) at commit `054aee1` (2026-09-21). linPEAS reports observable escape and privilege escalation evidence; it does not run Peirates' stateful attacks or import credentials into a session.

| Peirates commands | linPEAS check |
| --- | --- |
| `sa-menu`, `secret-to-sa`, `cert-menu` | Mounted service-account paths, kubeconfigs, client keys, certificate directories, projected and Secret volumes, and kubeconfig context names. Credential contents are suppressed by the Kubernetes module. |
| `ns-menu`, `get-pods`, `dump-pod-info`, `find-volume-mounts`, `list-secrets` | With `-a` or `-e`, names of accessible namespaces, pods, services, service accounts, Secrets and nodes; pod service accounts, host namespaces, container security settings and hostPath sources. Queries use kubectl when configured, or the mounted service account with `curl` and `jq`. Raw pod and Secret objects are not printed. |
| `aws-get-token`, `gcp-get-token`, `gcp-attack-kube-env` | Existing AWS and GCP cloud modules inspect workload metadata, IAM identities and GKE Kubernetes attributes. |
| `aws-s3-ls`, `aws-s3-ls-objects`, `aws-attack-kops-1`, `gcp-attack-kops-1` | With `-a` or `-e`, installed AWS and gcloud CLIs list accessible bucket names and candidate `/secrets/` object names. Up to 10 buckets and 100 objects per bucket are inspected; object bodies are not downloaded. This requires `timeout` and the corresponding CLI. |
| `attack-pod-hostpath-mount`, `exec-via-api` | Service-account RBAC for creating pods and pods/exec, plus existing mounted roots and visible hostPath sources. Admission controls still determine whether a new privileged pod could run. |
| `exec-via-kubelet`, `nodes-proxy-exec` | Kubelet config and process flags, general and node-specific `nodes/proxy` RBAC, and bounded unauthenticated reachability checks for node ports 10250 and 10255 under `-a` or `-e`. A port response does not prove execution permission. |
| `leakyvessels` | Visible upstream runc release compared with the CVE-2024-21626 affected range, plus pod-creation RBAC. Vendor backports and the node's actual runtime need separate confirmation. |
| `hostpid-breakout`, `hostpid-ptrace-breakout`, `hostroot-breakout` | Effective UID, relevant capability bits, namespace relationship to visible PID 1, distinct PID 1 root, executable shell, and mounted node-root candidates. These are prerequisites, not proof that PID 1 is the node init. |
| `container-escape-scan`, `docker-socket-breakout` | Runtime sockets and access modes, existing Docker API socket probe, cgroup controls, procfs, mounts and container isolation indicators. |
| `hostproc-core-pattern-breakout`, `nodefs-steal-secrets`, `hostlog-symlink-read` | `core_pattern` and cgroup controls on standard and alternate mounts, kubelet Secret/projected volumes at their original path or bind-mounted locations, writable host-log mount candidates, and `nodes/proxy` RBAC. |
| `kubectl`, `kubectl-try-all`, `kubectl-try-all-until-success`, `set-auth-can-i` | Local context names and, with `-a` or `-e`, bounded authorization listings for the current context and up to four others. linPEAS does not execute an arbitrary kubectl command or switch contexts persistently. |
| `enumerate-dns`, `tcpscan`, `curl` | With `-a` or `-e`, Kubernetes service SRV discovery and targeted kubelet port reachability. General arbitrary HTTP requests and full TCP port sweeps are utilities rather than Kubernetes escape checks. |
| `aws-enter-credentials`, `aws-assume-role`, `aws-empty-assumed-role`, `cd`, `pwd`, `ls`, `cat`, `shell`, `bash`, `sh`, `short`, `full`, `outputfile`, `exit` | Session controls and generic interactive utilities have no linPEAS check. Existing cloud and filesystem modules enumerate available evidence without changing active credentials or starting a shell. |

Local Kubernetes path and mount checks run when linPEAS sees Kubernetes environment or filesystem evidence, including a mounted node root or kubelet directory. API, DNS, kubelet and cloud-storage queries require linPEAS extra checks (`-a` or `-e`). The service-account API fallback requires readable token and CA files plus `curl` and `jq`; Kubernetes RBAC can limit its results. Network requests use short timeouts. Inventory limits include 60 Secret/projected-volume directories per scanned pod root, 10 mounted node roots, eight node addresses or node-specific RBAC reviews, and five alternate kubeconfig contexts. API collections request at most 100 objects and do not follow pagination. The Kubernetes module prints paths, names, permissions and statuses, not token, key or Secret values.
